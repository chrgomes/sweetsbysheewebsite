# Redesign plan

## Brand

The owner supplied the logo (original kept at `data/assets/originals/brand/`). The business name is
**Sweets by Shyee**; the domain is sweetsbyshee.com (different spelling, intentionally). The name and
asset paths live in `src/lib/brand.ts`; the name can be overridden in Admin → Settings.

| Asset | File | Used for |
| --- | --- | --- |
| Circular badge (transparent outside the ring) | `public/images/brand/logo.webp` | Header, footer, homepage hero (until a hero photo is set), admin, JSON-LD logo |
| Cupcake mark (transparent) | `public/images/brand/mark.webp` | "Photo coming soon" placeholders |
| Favicon / Apple touch icon | `src/app/icon.png`, `src/app/apple-icon.png` | Browser tabs, home-screen icons |
| Social sharing image | `public/images/brand/og.png` | Default Open Graph image (1200×630) |

The logo's tagline, "Homemade bakes · Freshly crafted", is used in the demo settings and can be set in Admin → Settings.

## Direction

Warm, sweet and refined, taking its palette straight from the logo, with an editorial layout so
photography leads.

| Element | Choice | Why |
| --- | --- | --- |
| Display type | Fraunces (variable, self-hosted) | Soft, characterful serif that sits comfortably beside the logo's script and roman capitals |
| Body type | Inter (variable, self-hosted) | Highly legible at small sizes and in forms |
| Palette | Blush paper `#fcefe9`, chocolate ink `#4a2414`, deep rose actions `#9a4d49`, logo rose `#c98278` and petal pink `#f2b6ad` for decoration | Matches the logo. The logo's own rose is too pale for text (2.7:1), so a deeper rose carries buttons and links |
| Shape | 1.25rem card radius, pill buttons, hairline borders | Soft and consistent; echoes the round badge |
| Motion | One gentle rise-in on the hero; colour/shadow transitions on hover | Enhances without delaying content; disabled under `prefers-reduced-motion` |

All text/background pairs meet WCAG AA: body ink ≈ 12:1 on blush, muted text ≈ 4.9:1, deep rose links
≈ 5.3:1, white on deep-rose buttons ≈ 6:1, petal on chocolate ≈ 6:1. Focus is a consistent 2px blue
outline with offset. Colours and fonts are tokens in `src/app/globals.css`; components reference only
those tokens.

## Homepage structure

Sections render only when they have verified content, so a half-migrated site never shows filler.

1. Announcement bar (owner-set, e.g. holiday deadlines)
2. Sticky header: logo, main nav, "Request a custom order" CTA, cart with count
3. Hero: owner headline/intro, two CTAs (shop / custom), hero photo
4. Featured products (owner-flagged; falls back to first products)
5. Category tiles (when there are 2+ categories)
6. Custom orders band with the three-step request process
7. Brand story (from settings)
8. Gallery strip
9. "Two easy ways to order" — explains checkout vs. custom request, with live lead times
10. Testimonials (owner-verified only)
11. FAQs (first five, native disclosure widgets)
12. Contact CTA with social links
13. Footer: shop/about/policies/contact

Newsletter sign-up is intentionally **not** included: it needs the owner's decision, a mailing
provider and a consent/privacy policy. It can be added as a section later.

## Key UX decisions

- **Two clear ordering routes.** Every product card states how it can be ordered ("Order online",
  "Custom order", or both). Products that are custom-only link straight to the request form with the
  product preselected.
- **No false promises.** The request form, confirmation page and acknowledgement email all say the
  request is not a booking until the bakery confirms. Customers must tick an acknowledgement.
- **Honest availability.** Checkout is offered only when the owner has configured tax and fulfilment
  rules and switched it on; otherwise the site explains how to order instead.
- **Lead times enforced, not just stated.** The date picker's minimum is the earliest bookable date,
  and the server re-checks lead time, open weekdays, blackout dates and booking window.
- **Mobile first.** Full-screen accessible menu with focus trap and Escape to close; 44px+ touch
  targets; horizontally scrolling category chips; sticky order summary on desktop only.
- **Forms keep what you typed.** Validation errors never clear the form.
- **Prices in text, not images**, with "From $X" when options change the price.

## Accessibility (WCAG 2.2 AA target)

Skip link, landmarks, one H1 per page, labelled inputs with hints and errors linked via
`aria-describedby`, `aria-invalid`, live regions for cart and price updates, native `<details>` for
FAQs, radio groups for options, alt text required for every uploaded photo, visible focus,
reduced-motion support. Automated e2e tests cover keyboard skip-link, mobile menu focus handling
and the absence of horizontal scrolling.
